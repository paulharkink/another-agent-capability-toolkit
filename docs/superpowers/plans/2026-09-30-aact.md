# Another Agent Capability Toolkit Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build the public Go Another Agent Capability Toolkit, port the seven approved packages, and prepare this repository to consume it, using TDD throughout.

**Architecture:** Source readers produce a normalized catalog consumed by shared installation, form and lifecycle operations. CLI and Bubble Tea TUI call those operations; optional generators compute Mustache data through JSON. Package-specific authentication lives in bundled package helpers, while agent configuration and ownership are managed through adapters and local state.

**Tech Stack:** Go 1.27.1; Bubble Tea v2.0.10; Lip Gloss v2.0.6; go-toml/v2 v2.4.3; cbroglie/mustache v1.4.2; ncruces/zenity v0.10.15; go-git/v5 v5.19.2; HuJSON commit `b80ff77dac4f3b606c8bf0a28a84b33e68d07f60`; Docker. Use Go's standard `flag`, `testing`, `os/exec`, `net/http`, JSON and archive packages rather than adding separate CLI/test/build frameworks.

**Spec:** `docs/superpowers/specs/2026-09-30-agent-manager-layout-design.md` and `docs/superpowers/specs/2026-09-30-agent-manager-open-source-design.md` in the current `agent-skills` checkout. Copy these approved documents into the new project so execution and review retain the source requirements.

## Global Constraints

- Install globally for selected configured agents/agent environments; a checkout selects catalog/configuration.
- Public project licensing is MIT; retain upstream attribution and notices.
- No system-wide Python, Go, Node.js, npm, jq or Make dependency for the manager or shipped package installation/lifecycle operations.
- Docker is a hard prerequisite for containerized MCPs and Docker-based tooling. The user owns host Docker readiness; assume it is available and run the required Docker tests.
- Versioned archives contain the executable, packages, templates and matching native helpers. Pin module versions and commit `go.sum`.
- Targets: macOS/Linux/Windows, each amd64/arm64; Windows executable for PowerShell/MinGW, Linux executable/state for WSL.
- Unix state root: `$XDG_STATE_HOME/agent-skills`, otherwise `~/.local/state/agent-skills`. Native Windows: `%LOCALAPPDATA%\aact\state`.
- One-at-a-time native/terminal file pickers; the manager owns collection Add/Edit/Remove.
- Form inputs feed `inputs` directly; optional generator results feed `generated`.
- CLI subcommands are noninteractive by default; `--interactive` opens editable prefilled forms.
- Keep existing agent integrations, inspector capabilities, external URL registration and legacy state/configuration compatibility.
- Do not push directly to `main`. All product/content changes intended for `main` go through pull requests.
- Do not use Computer Use. No live company/cluster/Grafana/Azure/Forgejo credentials or real agent installations are needed for build validation.
- TDD: write the test, observe its intended failure, implement the minimum, verify green, then refactor. Ported behavior gets preservation tests first.
- Marketplace adapters for OpenAI/Claude/Hermes and other formats are deferred.

## Shared Interface Contract

Task 1 defines these catalog structs in `internal/catalog/model.go` with TOML
tags matching the layout examples. These are contracts, not implementation bodies:

```go
type Package struct {
    SchemaVersion int
    ID, Name, Dir string
    Skill *Skill
    MCP *MCP
    Inputs []Input
    Templates []Template
    Generator *Command
}
type Skill struct { Name string; Files []string }
type Input struct {
    Name, ConfigKey, Type, Label string
    Required, Multiple bool
    Default any
    Min, Max *float64
    MinItems, MaxItems *int
    Options []Choice
}
type Choice struct { Value, Label string }
type Template struct { Source, Destination string }
type Command struct {
    Argv []string // TOML key: command
    Windows *Command
    TimeoutSeconds int
}
type MCP struct {
    Name, Runtime, BuildContext, Image, Transport string
    ContainerPort int
    EndpointPath, HostPortInput string
    Actions map[string]Command
}
```

`Type` supports the agreed scalar/choice/file/directory types. `Multiple` wraps
the scalar in a typed array. Reject a manifest containing neither skill nor MCP,
invalid IDs, unknown keys, conflicting source IDs or duplicate input names.
Default generator timeout is 300 seconds; manifests can declare another positive
timeout. Protocol stdout is limited to 16 MiB with an explicit size error.

Task 2 defines `config.Source{ID, Root, ManifestPath, EnvironmentRoot string,
Catalog []catalog.Package}` and `config.Target{Environment, Name, Path string,
Raw map[string]any}`. `Raw` retains existing package-specific TOML tables for
package validation; generic form resolution only maps declared fields.

Task 4 defines `state.Key{Source, Package, Environment, Target string}` and
`state.Installation{Key Key, AgentID, Component, Destination, SourcePath,
Mode, ReleaseID string, Digest string}`. IDs used in on-disk paths are encoded
with a stable hash; user-provided names cannot escape the state root.

Task 9 defines `mcp.RunSpec{Image string, BuildContext string, Args []string,
Env map[string]string, SecretEnv map[string]string, Mounts []Mount,
Host string, HostPort, ContainerPort int, Transport, EndpointPath string}`
and `mcp.Mount{Source, Destination string, ReadOnly bool}`. Do not persist
`SecretEnv` in the ownership ledger or logs.

Task 10 defines the package action request/response in `internal/mcp/actions.go`:

```go
type ActionRequest struct {
    ProtocolVersion int
    Action string
    Target config.Target
    Inputs map[string]any
    PackageDir, StateDir string
    Interactive bool
}
type ActionResult struct {
    AuthRequired bool
    Choices map[string][]catalog.Choice
    Runtime *RunSpec
}
```

Actions use JSON stdin and exactly one JSON object on stdout; stderr carries
progress. `prepare` validates target/config, derives options for already declared
questions, and returns a runtime plan or `AuthRequired`. `authenticate` is an
explicit action. It never runs a live sign-in from a noninteractive install.
Package helpers cannot introduce undeclared questions through `Choices`.

## Recovery and Rollback

- Failed generator/render: discard staging, leave old output/owned registration intact.
- Failed agent write: restore its prior file; record any independently successful agents so retry/removal is accurate.
- Failed state replacement: keep the previous valid record and temp diagnostics; retry through the lock.
- Failed container start: remove only that newly created owned instance, retain auth and existing registrations; report its logs without secrets.
- Failed release installation: keep prior launcher/version selection and resource directories.
- Failed migration preview/apply: no unowned resources are touched; preserve auth/settings backups and report exact conflicts.
- Failed overnight delivery/CI: leave commits, branches and archives available for recovery, with failed tasks unchecked.
- Under the proposed finish scope, rollback of delivered code is closing the draft PRs/removing the isolated new checkout after preserving artifacts. The current installed manager and real agent state have not changed.
