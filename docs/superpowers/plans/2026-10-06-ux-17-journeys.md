# AACT 17-journey UX implementation plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development. Steps use checkbox syntax. The user has authorized execution without another plan presentation.

**Goal:** Implement every “How this should behave” requirement from all 17 journeys, with a consistent keyboard-first blue TUI and truthful operation state.

**Architecture:** Retain existing Go/Bubble Tea domain services, adapters, input model and ledger. Consolidate existing TUI routes into a shared target workspace; add an embedded fallback picker and structured progress/error views. Internal helper APIs are implementation seams, not a new persistence/plugin architecture.

**Tech Stack:** Go 1.27.1, Bubble Tea v2, Lip Gloss v2; current repository dependencies.

**Spec:** docs/superpowers/specs/2026-10-06-ux-17-journeys.md; illustrated reference docs/ux/review-2026-10-06/index.html. Later user approval turns those proposal lists into the binding implementation scope.

## Global Constraints

- Implement all 17 journeys from docs/superpowers/specs/2026-10-06-ux-17-journeys.md; the illustrated report is the visual reference.
- All implementation and implementation fixes belong to Luna subagents (gpt-6-luna). The controller may plan, coordinate, inspect, run verification, and manage Git, but may not implement product code or tests. Ask the user before using any higher model, including reviewers.
- Maximize parallel work with explicit disjoint file ownership. Shared-file changes wait for their dependencies. No subagent may spawn another subagent.
- TDD: write and observe the intended failing interaction/service test before production code; record RED and GREEN commands/output. Tests assert actual model/service/filesystem behaviour, not a fake backend declaring success.
- L1 left overview -> Enter focuses L2. L2 related actionable detail -> Enter opens L3. L3 with detail has L4 beside it, inset and at least one row below the underlying L1/L2. A simple L3 is a narrower centred dialog.
- Up/Down and scrolling affect only the focused pane. L3 selection changes L4 content; L4 navigation never moves L3. Left/Right and Tab move pane focus, except Left/Right edit text when a field is active. Tab reaches every visible action button. Mouse is optional.
- Enter edits a text/path field in place with its existing value. Terminal paste is handled. Backspace edits text, or removes a selected collection row outside text editing. Browse/Add are explicit controls. Ctrl-S finishes the active edit, validates, saves once and applies immediately.
- Keep one blue palette, meaningful titles/identity, visually distinct non-action facts, visible focused pane, and explicit above/below scroll indicators. A position count alone is not a scroll indication.
- Token and Source kubeconfig are exclusive alternatives. Inactive alternatives remain focusable so editing switches the mode. Source kubeconfig is imported, not a live runtime path. Do not mask values. Target-fixed inputs are hidden; defaults are editable. Fixed is target TOML only.
- Preserve submitted answers/drafts on apply failure and distinguish Saved from Applied. Show exact child error/step/target in a foreground recoverable result with wrapped output. No automatic state revert, no false successful registration checkbox. Ordinary cancellation is not an operation failure. Back retains unsaved draft; explicit Cancel discards it.
- Skill-only All defaults to ~/.agents/skills. MCP destinations/registration/default choices contain named adapters only, never All or generic. Keep the generic adapter for existing skill-only/legacy compatibility; enforce MCP UI operation boundaries, not just labels.
- Package, preset, configured target, runtime observation/ownership, endpoint reachability, and achieved agent registration remain separate. An unknown/foreign runtime is not locally startable/stoppable but can be registered to a local named agent.
- Preserve existing noninteractive CLI, installation ledger/schema, OS-native config rules, source/target path semantics, and compiled agent adapters. Extend existing optional UI service contracts instead of introducing a new plugin/runtime architecture.
- No live user agent config, credentials, MCP instances, or migration records may be modified in build/test. Use temp homes/state, fake process/runtime adapters where required, and label fixtures. Do not use Computer Use. No new tmux sessions. Live TUI work must use an existing session; model/render tests can run normally.
- No direct main push, merge, release, tag, publication, or live deployment. During parallel work the controller owns commits/go.mod/go.sum; subagents report scoped changes, never stage or commit another agent's files.
- Go toolchain: /tmp/aact-ux-go1.27.1/sdk/bin/go, with PATH=/tmp/aact-ux-go1.27.1/sdk/bin:$PATH. Baseline go test ./... -count=1 passed (see /tmp/aact-ux-17-tooling.md). Parallel tasks run focused tests; full-suite integration gates run when each wave is quiescent and at final completion. Do not claim Docker/OS integration tests ran unless they did.

## Review Focus

- A profile with old recorded/custom home and JSON plus JSONC must explain exact native/effective/planned/recorded paths (Task 1).
- Bracketed Unicode paste, an invalid partially edited field and Ctrl-S must neither lose text nor submit twice (Task 2).
- An unavailable native picker must not fall into stdin prompting; Escape restores parent field (Tasks 3–4).
- Auth/generation/start/registration may fail after inputs save; exact output, retained draft and per-effect ledger must agree (Tasks 6–9).
- Resizing or navigating L4/Logs/management cannot move L3 or lose keyboard actions (Tasks 7–12).
